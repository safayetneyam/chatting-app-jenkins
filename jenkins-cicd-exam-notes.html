CI/CD & Jenkins — Exam Study Notes

(Organized by the 10 official marking criteria — 5 marks each)

1. CI/CD (5 marks)

  • CI/CD concept: why CI/CD is used, what benefit it provides, what problem it solves, and why it is necessary to integrate CI/CD into a project

2. Jenkins Functionality — Credentials, Role Management, Node/Multi-node, Webhook, Pipeline Structure (5 marks)

Credentials / Secrets

  • How to give Jenkins permission (access control)
  • How to create secrets
  • env — secret: using environment variables to hold secrets
  • Secret text token: storing a token as a "Secret text" credential

Role Management

  • How to create a user
  • How to create a role
  • How to change your profile password

Node / Multi-node

  • Basic node settings
  • Number of executors — what it means and why you'd choose 1, 2, or 3
  • How to add a multi-node (agent) setup
  • Benefit of using multiple nodes

Webhook

  • How webhook works (triggers a Jenkins build automatically on a repo event, e.g. a Git push)

Pipeline Structure

  • What is a Pipeline job
  • What is a Freestyle job
  • Why use Pipeline over Freestyle
  • Why use folders (to organize jobs)
  • What "duplicate" (job) means and its benefit
  • How to remotely access Jenkins using tokens:
    • Add a new API token from Security settings
    • Used when another application needs to remotely trigger Jenkins builds
    • Example: pass the Jenkins URL/domain to allow another application to remotely execute specific builds

3. Jenkins Installation (5 marks)

  • Plugin installation
  • Tools settings — how to use them
  • Security settings — how to use them
  • Where to set up the email server (email configuration)

4. Jenkinsfile Syntax (5 marks)

  • Explain the syntax of a Jenkinsfile

5. Jenkinsfile vs Inline Syntax (5 marks)

  • Remote Jenkinsfile (stored on GitHub) vs inline script (written directly in the Jenkins job)

6. Shared Library (5 marks)

  • Structure: a vars folder containing .groovy files
  • Each .groovy file defines a stage as a function, written in Groovy script
  • These functions/scripts are then called from a Jenkinsfile
  • Setup steps:
    • Go to shared library settings
    • Set the library name
    • Add the Git repo link
    • The repo root must contain the vars folder
  • Reference: https://phoenixnap.com/kb/jenkins-shared-library

7. DevOps vs DevSecOps (5 marks)

  • Compare and explain the difference

8. Security Tools for DevSecOps — Open Source (5 marks)

  • List the names of well-known open source security tools used in DevSecOps
  • Standard DevSecOps steps, in sequence, noting which stages depend on order and which don't:
    • Example: a Trivy scan of the built image must happen after the image is built
    • Example: a Trivy scan of the overall filesystem does not necessarily need to happen after the image is built

9. Standard Implementation of a Jenkinsfile (5 marks)

  • Mother block: the top-level pipeline block
  • Stages block hierarchy: how stages and stage are nested, and where the curly brackets go
  • Single-line command: using sh 'command'
  • Multi-line command: using triple double-quotes sh """ ... """
  • Script block: used for multi-line/scripted logic (script { ... })
  • def: how to define and use a function (def) inside a script block

10. Full End-to-End React Project Showcase (5 marks)

  • Demonstrate a complete end-to-end pipeline using the React project, including security stages
  • Show that pipeline artifact files are generated
  • Show that these artifact files are downloadable
